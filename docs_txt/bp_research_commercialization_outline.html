科研成果商业化项目 — 商业计划书标准（纲领）

与机器模块清单对应文件：config/bp_transform_outline_registry.json（registry_version: 2）
详细话术、表格模板、模型（PEST/五力/钻石等）：bp_research_commercialization_templates.html
代码与 artifact 契约（上游）：kt_workflow_contracts.html
中游章节生成（组员必读）：kt_workflow_chapter_writer_guide.html

文档说明

核心原则

  1. 证据锚定：所有数据标注【事实 / 推断 / 待验证】（见 0.3 来源优先级）。
  2. 双视角穿透：同时满足校方（学术价值）与企方（商业可行）。
  3. 适度简化：科研团队 BP 重点在「资源需求」，避免过度商业化与脱离证据的收益预测。

模块化写作与 JSON 的对应关系

  • 每个 modules[] 项 = 一次独立生成单元：id 即 bp_module_text / bp_module_chart 的 slug。
  • 可选字段 writer_hint：字数、必选表、模型名等提示，已写入注册表并进入桩正文的「写作提示」与 artifact meta_json。
  • needs_chart: true：必须配 同 id 的 bp_module_chart（版式图、结构图或表格渲染说明）。

重新生成注册表：

python scripts/build_bp_transform_registry.py

用户需提供信息（收集表）

必须提供

  1. 成果基础：成果名称、领域、一句话用途
  2. 技术核心：原理（通俗）、3 个创新点、3～5 项核心参数
  3. 验证数据：实验室/小试关键结果
  4. 知识产权：专利/软著数量与状态
  5. 团队核心：1～2 名骨干（姓名、职称、职责）

可选提供

技术补充、市场偏好、初步规划、合作意向等（见模板文档）。

编审提示（实施时注意）

  1. 5.1 总字数 600～800 与 4 个子模块（5.1.1～5.1.4）：并发生成时易超标；建议在 LLM 层对 5.1.x 统一预算或改为「单模块生成整节 5.1」如需严格控长。
  2. 3.6「技术壁垒」与 6.4「技术壁垒」：建议 3.6 偏技术机理与专有 know-how，6.4 偏专利组合、布局与团队 IP 运营，避免完全重复。
  3. 阅读对象矩阵：生成前须确定对象；未选中的「可选」章可由用户开关或 structured_profile/入参驱动（后续可在 state 增加 reader_persona）。
  4. 证据：凡市场/财务数字须可回溯来源；无法满足打【待验证】并在附录列清单。

版本与变更

  • 大纲或模块 id 变更：registry_version +1，并同步本文件「目录」表。
  • 话术大改：主版本；小节边界/字数：registry_version 或文档次版本说明即可。
